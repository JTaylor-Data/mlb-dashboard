# MLB Dashboard

A FastAPI + static-JS web application that scores MLB pitchers on four proprietary
metrics — Stuff+, Location+, Tunneling+, and Deception+ — built on top of Statcast
data from Baseball Savant.

---

## What it does

| Model | What it measures | Seasons |
|---|---|---|
| **Stuff+** v4 | Pitch shape: velocity, movement, spin | 2016–2026 |
| **Location+** v3 | Where pitches land given count, pitch type, and batter handedness | 2015–2026 |
| **Tunneling+** v2 | How similar pitches look to each other at the commit point | 2015–2026 |
| **Deception+** v2b | Pitcher body/release mechanics (arm angle, extension, consistency) | 2021–2026 |

All four are scaled to 100 = league average; higher is better for the pitcher. Each
uses an empirical-Bayes or min-pitch-count approach to handle small samples.

---

## Stack

- **Backend**: Python 3.11, FastAPI, Uvicorn, APScheduler, SQLite (WAL mode)
- **ML**: LightGBM boosters (`.txt` files in `models/`), pre-computed score parquets in `scores/`
- **Frontend**: Vanilla JS, static HTML/CSS served by FastAPI `StaticFiles`
- **Data**: pybaseball Statcast pulls, MLB Stats API (rosters, injuries, schedule)
- **Hosting**: Render (Docker); persistent disk at `/data` holds `mlb_data.db`

## Running locally

```bash
# Install dependencies
pip install -r requirements.txt

# Start the server (database path defaults to ./mlb_data.db)
DB_PATH=./mlb_data.db uvicorn api.main:app --port 8010 --reload
```

Open `http://localhost:8010` in a browser.

### Docker (matches Render deploy)

```bash
docker build -t mlb-dashboard .
docker run -p 8010:8010 \
  -e DB_PATH=/data/mlb_data.db \
  -e SEASON_PHASE=POSTSEASON \
  -v "$(pwd)/mlb_data.db:/data/mlb_data.db" \
  mlb-dashboard
```

### Running tests

Tests require a live server on port 8010:

```bash
DB_PATH=./mlb_data.db uvicorn api.main:app --port 8010 &
pytest -q
```

Expected: **198 passed, 1 skipped, 2 xfailed** (the skipped/xfailed items are
Tunneling+ v3 artifacts that are not present on most machines).

## Deployment (Render)

Defined by `render.yaml`. A persistent disk at `/data` holds the database between
deploys. `start.sh` creates a stub database at startup if the disk is empty, so the
server always boots cleanly. See `docs/HOSTING.md` for the full deployment guide.

Required environment variables:

| Variable | Example | Notes |
|---|---|---|
| `DB_PATH` | `/data/mlb_data.db` | Path to the SQLite database |
| `SEASON_PHASE` | `POSTSEASON` | `REGULAR_SEASON`, `POSTSEASON`, or `OFFSEASON` |
| `ADMIN_TOKEN` | (secret) | Guards `/api/admin/*` endpoints |

---

## Data pipeline

Nightly pulls (via APScheduler) update Statcast pitch data, team standings, rosters,
injuries, and probable pitchers. On startup, `warmup.py` loads pre-computed score
parquets into memory so the first request is fast.

Model retraining is **not** automated — see `docs/methodology/NEEDS_DECISION.md`
(ND-01) for the annual retrain decision.
