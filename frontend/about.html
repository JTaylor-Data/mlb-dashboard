How these were built

Each model started from a clear question about what it should and shouldn't measure â€” deliberately separated so they can eventually be stacked as inputs to a combined Pitching+ metric rather than blending overlapping signals into one number.

Validation was iterative and honest. Several real issues were caught and fixed during development: a pairwise distance calculation in Tunneling+ that was using centroid-to-centroid averaging (silently halving the measured separation for high-variance pitchers), a collinearity artifact in Deception+ where arm_angle and release_pos_z (r = 0.79) split the same signal across two features in ways that made the individual SHAP contributions misleading, and a Spring Training contamination bug in the data pipeline that inflated pitch counts across all six seasons until it was caught and purged.

The methodology documents under each model page go into the full detail â€” train/test setup, feature importance, predictive validity across consecutive seasons, and the specific diagnostic checks run to confirm each model captures something real.

Tech stack

Real Statcast pitch-by-pitch data pulled via pybaseball and the MLB Stats API for every regular-season game from 2021 through the current 2026 season (~3 million pitches). All stored in a single SQLite database.

Models are trained offline in Python (LightGBM, scikit-learn) and served live via FastAPI. The frontend is plain HTML/CSS/JS with hand-built SVG charts â€” no charting library.
