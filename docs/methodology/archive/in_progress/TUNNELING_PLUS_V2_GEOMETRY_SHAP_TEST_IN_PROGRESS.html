The prior Part 4 test (z = 180.1) was close to circular: it bucketed pitches by the model's full blended xRV, which already incorporates the model's own xWhiff% prediction as one of five inputs. When the geometry features are isolated — independent of pitch-type information — they show no predictive signal for real whiff rates. Tunneling+ v2's xWhiff% component is primarily learning pitch-type sequencing, not geometric tunneling.

Why the Prior Test Was Insufficient

The prior Part 4 sequential test bucketed pitches by the full blended xRV (xSwing% × xWhiff% × xFoul% × BIP×EV + xCS% combined via a run-value table). One of those five inputs is the model's own predicted xWhiff% probability — which is computed from the same lag-geometry features we're trying to validate. Asking "does the model's full xRV output predict real whiff rate?" and then finding z = 180.1 is therefore unsurprising but uninformative: the model's direct xWhiff% prediction was riding along in the xRV numerator.

The correct question is: do the lag-geometry features specifically predict real whiff rate on their own, independent of pitch-type identity? This test answers that question directly.

Methodology

Step 1 — Load xWhiff% classifier only

Used tunneling_plus_v2_xwhiff.txt (one of the five v2 classifiers) in isolation. The xWhiff% sub-model takes all 28 features: 18 numeric lag columns (lagN_{commit_distance, plate_distance, shape_break} for N=1–6) and 10 categorical columns (6 lagN_pitch_type + pitch_type, p_throws, stand, season).

Step 2 — Compute SHAP values

Used shap.TreeExplainer on a stratified random sample of 200,000 rows from the 2021–2025 commit-table corpus (2,635,868 total lag rows). Sample preserves the 13.6% overall whiff rate.

Step 3 — Three isolated scores

ScoreFeatures summedPurpose
lag1_geom_shap lag1_commit_distance, lag1_plate_distance, lag1_shape_break Primary result: lag-1 geometry only (closest analog to the original v3 consecutive-pair test)
alllag_geom_shap Same 3 features × all 6 lag slots (18 total) Secondary: does geometry matter at any lag depth?
pt_lag_shap lag1_pitch_type … lag6_pitch_type Confound control: pitch-type sequencing only — how much of any whiff effect is just pitch-type history?

Step 4 — Tercile z-test

For each score, bucket 200K rows into low/mid/high terciles. Compute real whiff rate per tercile. z-test = (high_score whiff − low_score whiff) / pooled SE. Sign: positive z means high SHAP score (model says features push xWhiff% up) → more real whiffs, which is what we would expect if the signal is genuine.

What This Means

The lag-geometry features have no isolatable predictive signal for real whiff rates. The model's ability to discriminate xWhiff% comes from pitch-type sequencing (z = 18.6), not from the geometric commit/plate/shape-break distances that motivated the tunneling feature design. The prior z = 180.1 result was not a validation of the geometry concept — it was mostly a test of whether the model's embedded whiff probability predicted whiff (trivially yes) and pitch-type sequencing effects (genuinely real but not tunneling-geometry-specific).

Important caveats

  • This is SHAP attribution for xWhiff% only. The geometry features may have signal in the other four classifiers (xCS%, xFoul%, BIP type × EV, xSwing%). This test only isolates xWhiff%.
  • SHAP attribution ≠ marginal effect. Tree SHAP measures each feature's individual attribution holding others fixed, but interaction effects between geometry and pitch-type are distributed across both feature groups. The geometry features may contribute through interactions that SHAP attributes to pitch_type.
  • Sample is 200K of 2.6M rows. The z-scores of ±1.7 and +1.6 are precise enough at this sample size to rule out any meaningful effect — a real effect would produce z >> 10. This is not a power concern.
  • The model stays live. This is a validation-quality diagnostic, not a promotion decision. Tunneling+ v2 replaced v3 to fix a sign-flip in ERA/xFIP correlations, which remains resolved. This finding does not reverse that decision.
What the geometry features might still be doing: The commit/plate/shape-break distance features capture real physical measurements of pitch-to-pitch similarity. They may improve xCS% (called-strike positioning), xSwing% (inducing swings), or BIP quality control more than xWhiff% specifically. A fuller test would run this same SHAP isolation across all five sub-models. For now, the xWhiff% result is the clearest signal because it's the outcome most directly linked to the "hitter confusion" theory behind tunneling geometry.

For future Tunneling+ work

  • Run the same SHAP isolation on xCS%, xSwing%, xFoul% to see if geometry features have signal in other outcome classifiers.
  • Consider whether the geometry features should be replaced or supplemented with features that more directly capture batter perception difficulty (e.g., release-point distance for consecutive pitches from a hitter's perspective).
  • The pitch-type sequencing signal (z = 18.6) is real and worth preserving in any redesign — it should be explicit rather than implicit in the lag_pitch_type categorical feature.
