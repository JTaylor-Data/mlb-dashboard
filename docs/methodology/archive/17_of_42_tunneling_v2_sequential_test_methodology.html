Methodology

This test adapts the v3 validation methodology (from training/validate_tunneling_plus_ext.py) for the live v2 decomposed-classifier boosters.

Procedure

  1. Load all non-1st-pitch-of-PA rows for 2021–2025 using sequential_lag_features()
  2. Score each pitch with all 5 v2 classifiers → combine via run-value table → per-pitch xRV
  3. Bucket by predicted xRV into terciles: low_xrv (good tunneling), mid_xrv, high_xrv (bad tunneling)
  4. Compute real whiff rate per tercile
  5. z-test: (low_xrv whiff rate − high_xrv whiff rate) / pooled standard error
Sign convention: lower xRV = better for the pitcher (harder pitch to hit). So low_xrv tercile = good tunneling = should yield higher whiff rate. The z-score tests whether the difference is real: z = 180.1 is overwhelmingly significant (p ≈ 0).

Scope note: 2021–2025 only

The commit-point table at training/tunneling_v2_artifacts/200ms/pitcher_season_commit_point.csv covers 2021–2025 (4,854 pitcher-seasons). Seasons 2015–2020 were skipped because their pitcher-season commit points are absent, so sequential_lag_features() dropped those rows. The 2,635,868 rows from 2021–2025 are sufficient for a definitive test.

Why v2 z > v3 z despite a smaller corpus? The decomposed-classifier architecture produces xRV predictions that are better calibrated to the underlying difficulty-to-hit signal. Each pitch gets a probability distribution over 5 outcome events combined with a fixed run-value table — the model explicitly decomposes "how hard is this pitch to hit" into its constituent events. The v3 single regressor directly predicted delta_run_exp, which may have absorbed some noise into the regression target. The v2 signal is cleaner per-pitch.

Limitations

  • 2021–2025 only: the commit table doesn't cover 2015–2020, so this test omits 6 seasons of data the model was trained on. Not a concern for validity — just a scope limitation.
  • Not comparable to v1/v2 (old) z-scores: those used pair-level scores; this uses per-pitch xRV. Different measurement structures.
  • Whiff rate ≠ full outcome quality: whiff is one of five outcomes in the model. The test checks whether the model's ranking correlates with one outcome; ERA/xFIP correlations (in the v2 validation battery) are the fuller picture.
