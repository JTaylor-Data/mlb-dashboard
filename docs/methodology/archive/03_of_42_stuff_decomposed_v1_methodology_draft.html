1. Purpose — Why This Was Built

The 2026-09-21 validation session tested whether the decomposed classifier architecture (five binary/multiclass classifiers → run-value table → plus-scale) is a general improvement over the direct LightGBM regressor approach used by Stuff+ v3.

The hypothesis: if classifiers fix the sign-flip in Location+ v1 and Tunneling+ v3, do they also improve Stuff+?

Result: no. Stuff+ v3 uses a direct Huber-loss regressor, and that approach is superior for the Stuff+ feature set. The decomposed architecture only helps when the feature set directly drives outcome classification (plate location → called strike, lag context → swing), not when the features are more indirect physical properties.

The split-half vs. YoY discrepancy is real. Split-half r = 0.992 for both means the model is highly reliable within-season — a pitcher's first-half score predicts their second-half score. But YoY stability dropped from 0.907 to 0.830 — the decomposed v1 is noisier across seasons. The five classifiers + run-value table pipeline apparently introduces more aggregation variance year-to-year than the direct regressor. Stuff+ v3's direct approach is better-suited to its features.

5. What This Study Confirms

The decomposed classifier architecture is not universally superior. It provides clear benefits when:

  • The feature set directly determines outcome classification (e.g., plate_x/plate_z → called strike for Location+)
  • The live model had a sign-flip caused by direct run-value regression (Location+ v1, Tunneling+ v3)

It does not improve on Stuff+ v3 because:

  • Physical pitch shape features (velo, spin, movement) are more indirectly linked to per-pitch outcome classification — the classifiers work at AUC 0.55–0.64, not 0.75+
  • Stuff+ v3 had correct sign (ERA r = +0.222) and no stability problems to fix
  • The live regressor already achieves near-perfect split-half reliability (0.992) — there was no headroom to gain
